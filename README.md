# MOODua — наскрізна аналітика

Next.js 15 + Postgres + NetHunt CRM. Розгортається на Vercel.

Дашборд рахує ліди, угоди та витрати на рекламу в одному місці й показує ROMI по кожному джерелу.

---

## Головне про методологію

**Угода належить місяцю, коли надійшов запит (`Дата - Запит`), а не місяцю, коли вона закрилась.**
Це і є когортна атрибуція: якщо лід прийшов у травні, а угода закрилась у серпні, вона рахується
травню — бо травень оплачував рекламу, яка її привела. Раніші версії звіту рахували по даті
закриття, і саме через це цифри не сходились із бюджетною таблицею.

Інші правила, зашиті в код:

| Правило | Де |
|---|---|
| Аутбаунд не потрапляє в маркетингову звітність узагалі | `src/lib/taxonomy.ts` → `OUTBOUND_SOURCES` |
| Довідник джерел має українські та англійські значення (зміна ~липень 2026) — мапляться обидва | `SOURCE_MAP` |
| «Інстаграм» до липня не ділився на Paid/Organic — лишається окремим кошиком | `SOURCE_MAP` |
| Нове значення джерела, якого немає в мапінгу, потрапляє в лог синхронізації, а не зникає | `src/lib/sync.ts` |
| Прибуток = виручка × маржа з `NEXT_PUBLIC_MARGIN` (за замовчуванням 15,26%) | `src/lib/metrics.ts` |
| ROMI = прибуток ÷ витрати. Поріг окупності — 100% | `src/lib/metrics.ts` |

## Запуск

```bash
npm install
cp .env.example .env.local     # заповнити змінні
npm run db:push                # створити таблиці
npm run db:seed                # завантажити бюджет і метрики Meta
npx tsx scripts/sync-cli.ts --full   # перший повний імпорт з NetHunt
npm run dev
```

### Змінні оточення

| Змінна | Що це |
|---|---|
| `DATABASE_URL` | Postgres. Підійде Neon, Vercel Postgres або Supabase |
| `NETHUNT_EMAIL` | Gmail-адреса, на якій працює NetHunt |
| `NETHUNT_API_KEY` | NetHunt → Settings → NetHunt CRM → API key → Generate |
| `NETHUNT_DEALS_FOLDER` | `66570201a83a751d7c5460a2` |
| `NETHUNT_LEADS_FOLDER` | `6a316a22b22cc61f6e9d5ec5` |
| `SYNC_SECRET` | Спільний секрет для `POST /api/sync` |
| `NEXT_PUBLIC_SYNC_TOKEN` | Те саме значення, доступне кнопці «Оновити» в браузері |
| `NEXT_PUBLIC_MARGIN` | Маржа для розрахунку прибутку, напр. `0.1526` |

`NEXT_PUBLIC_SYNC_TOKEN` видно в браузері — це нормально для внутрішнього дашборда,
але якщо адреса буде публічною, приберіть його й закрийте застосунок Vercel Authentication
(Project → Settings → Deployment Protection), а кнопку переведіть на server action.

## Розгортання на Vercel

1. Залийте репозиторій у GitHub, імпортуйте проєкт у Vercel.
2. Додайте Postgres: Storage → Create → Neon, змінна `DATABASE_URL` підставиться сама.
3. Додайте решту змінних оточення.
4. Deploy. Після першого деплою один раз запустіть локально `db:push`, `db:seed` і
   `sync-cli.ts --full` — вони працюють проти тієї самої бази.
5. Cron уже описаний у `vercel.json`: `/api/sync?cron=1` щодня о 05:30 UTC (08:30 за Києвом).

---

## Кнопка «Оновити»

Поруч зі штампом «Оновлено …» у шапці. Натискання робить `POST /api/sync`, який:

1. бере дату останньої вдалої синхронізації з таблиці `sync_log`;
2. запитує в NetHunt лише записи, змінені відтоді (з перекриттям 6 годин, щоб не втратити
   картку, відредаговану під час попереднього запуску);
3. нормалізує джерела, відкидає аутбаунд, рахує когортний місяць;
4. робить upsert у `deals` і `leads`;
5. повертає, скільки записів оновлено і які нові значення джерела зустрілись.

Повний перезбір — `POST /api/sync?full=1`.

## Структура

```
src/
  db/schema.ts        таблиці: deals, leads, budget, meta_stats, sync_log
  lib/nethunt.ts      клієнт NetHunt REST API (Basic auth, пагінація, backoff)
  lib/taxonomy.ts     мапінг джерел, кольори, список аутбаунд-значень
  lib/sync.ts         NetHunt → Postgres
  lib/metrics.ts      агрегації (когорти, воронка, витрати)
  app/api/sync        POST — синхронізація, GET — те саме для крона
  app/api/metrics     GET — дані для дашборда
  components/Dashboard.tsx   UI: Dashboard / Ліди / Угоди / Джерела
scripts/
  seed-budget.ts      бюджет і метрики Meta з data/budget-2026.json
  sync-cli.ts         разовий повний імпорт
```

## Що ще треба зробити руками в NetHunt

1. **Додати опцію `Instagram Paid`** у поле «Джерело» папки «Всі угоди». Доки її немає,
   ROMI по Meta порахувати неможливо — дашборд показує лише верхню межу («ROMI стеля»).
2. **Зробити поле «Джерело» обов'язковим** при створенні угоди.
3. **Прибрати дублі в довіднику** — залишити один набір значень замість українського й
   англійського паралельно.
4. **Додати поле з датою передачі в Sales** у папці «Ліди». Зараз час обробки рахується як
   проміжок від створення картки до останньої зміни — це проксі, а не факт.

Google Ads і Search Console поки не підключені: у дашборді видно лише витрати з бюджетної
таблиці, без показів, кліків і позицій.
